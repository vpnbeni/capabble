# Capabble mobile app

iOS and Android app for families and staff: the design system's Companion surface.
Expo SDK 58, Expo Router, TypeScript. Plan and decisions: `docs/requirements/mobile-app-plan.md`.

## Set up

Needs Node 22.13 or later (`.nvmrc`: 24). This folder is its own npm project, not a workspace:

```bash
cd mobile && npm install
```

## Run

```bash
npm start            # Metro; press i for the iOS simulator, a for Android, w for web
npm run ios          # straight to the iOS simulator
```

- Expo Go runs the app as it is today. Once a library with its own native code is added,
  use a development build (`npx expo run:ios`, or `eas build --profile development`).
- The API: in development the app calls port 5000 on the machine running Metro, so a phone on
  the same Wi-Fi works. Set `EXPO_PUBLIC_API_URL` in `.env.local` to use another one (see `.env.example`).
- The web preview (`npm run web`) can only sign in against an API whose `NODE_ENV` isn't
  `production`, because of CORS. Phones and simulators send no `Origin`, so they always can.

## Check

```bash
npm run type-check
npm run lint
npm run doctor       # expo-doctor: SDK version mismatches, config problems
```

## Layout

| Path | What |
|---|---|
| `src/app/` | Routes (Expo Router). `sign-in.tsx`; `(app)/` is the signed-in tab shell |
| `src/ui/` | The native kit. Read `src/ui/DESIGN.md` before building a screen |
| `src/theme/` | Tokens from `packages/shared/src/designTokens.json`, light and dark |
| `src/lib/` | API client (cookies, tenant header, refresh), config, storage, formats |
| `src/services/` | API calls per area, mirroring `client/src/services` |
| `src/session/` | Signed-in user and school |

`ios/` and `android/` are generated by Expo and never committed or edited by hand.
